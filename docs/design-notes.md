# 设计笔记：为什么这样选

> 记录项目里的判断依据，方便面试时讲清楚“为什么”，而不是只报指标。

## 1. 为什么用公开指南而不是自己造文档

- 指南有明确版本、页码、推荐等级，答案可核对；
- 医学问题天然存在“同一句话出现在多个章节”的情况，能暴露真实检索难点；
- 不需要编造业务数据，指标可复现。

## 2. 为什么切 450 字、重叠 80 字

- 中文指南一段通常 200~500 字，450 字能把一个完整推荐及其限定条件放在一起；
- 80 字重叠保证跨 chunk 的句子不被切断；
- 没有按 token 切，是因为当前模型 512 token 上限，450 汉字约 300~450 token，
  留有余量；后续换 bge-m3 可改为 token 计数。

## 3. 为什么 BM25 首位命中反而最好

- 指南问题里大量专有名词（“白大衣性高血压”“UACR”“SGLT2i”），BM25 精确匹配
  非常强；
- bge-small-zh 只有 512 维，语义区分度有限，容易把“定义”“治疗”“预后”混在
  一起；
- 所以单看向量指标会误判，混合检索的 Recall@5 才是关键收益。

## 4. 为什么用 RRF 而不是加权分数

- BM25 分数无上界，向量余弦在 [-1,1]，直接加权需要调参且换语料就失效；
- RRF 只用名次，`k=60` 是常用默认值，鲁棒；
- 代价是首位排序被平均掉，正好交给重排解决。

## 5. 典型 badcase

| 问题 | 现象 | 原因 |
| --- | --- | --- |
| 白大衣性高血压的定义 | BM25 Top5 全是“预后/治疗”段落 | “白大衣性高血压”在多个章节反复出现，定义段反而短 |
| 2 型糖尿病何时用 SGLT2i | Top1 是高血压指南的血糖章节 | 两份指南有重复推荐，单 gold 标注偏严 |
| 糖尿病肾病筛查指标 | Top1 是视网膜病变段落 | “糖尿病肾病”与“DR”常并列出现，词面重叠 |

这些 badcase 说明：**单路召回不够，重排和文档级去重都需要**。

## 6. 拒答阈值怎么定

- 重排输出是 logit，不是概率，不能直接说“置信度 0.8”；
- 当前用固定阈值，在评测集上观察“正确命中”和“无关问题”的分数分布后确定；
- 更严谨的做法是留出集上按目标拒答率定阈值，或训练一个校准层；
- 这是项目目前的已知不足，也是下一步要补的实验。
